# Learning Unit Authoring Guide

## Recommended structure

1. **Why it matters** — 2–4 câu gắn với hệ thống thật.
2. **Learning objectives** — tối đa 3 objective chính.
3. **Prerequisite check** — nhắc những concept cần biết.
4. **Resource focus** — link + section + điều cần chú ý.
5. **System explanation** — mental model ngắn.
6. **Worked example** — lời giải mẫu từng bước.
7. **Guided practice** — có hint/scaffold.
8. **Independent practice** — user tự làm.
9. **Retrieval check** — đóng tài liệu, trả lời/giải thích.
10. **Review intent** — concept nào sẽ được hỏi lại.

## Writing level

- Viết cho sinh viên đã biết các prerequisite, không viết cho expert.
- Một đoạn nên ngắn và tập trung một ý.
- Code sample ưu tiên ngắn, có mục đích rõ.
- Không giải thích framework bằng magic; chỉ ra request/data flow khi có thể.

## Resource rule

Không ghi chỉ:

> Đọc MDN HTTP.

Phải ghi:

> Đọc phần HTTP flow và HTTP messages. Hôm nay tập trung request method, status code, headers/body; bỏ qua proxy/cache nâng cao.

## Practice ladder

`See → Complete → Modify → Build` là default cho novice, nhưng không bắt mọi unit phải đủ cả bốn nếu không cần.

## Completion criteria

Learning unit `COMPLETED` khi user đã đi hết required activities. Mastery vẫn được tính riêng từ evidence.
