# Plan Feature

1. Read `AGENTS.md`, `docs/00-governance/docs-index.md`, and `docs/00-governance/simplicity-guardrails.md`.
2. State the user problem and expected outcome.
3. Identify whether learning behavior changes; if yes, read `docs/02-learning/`.
4. Map the UX flow and mandatory states.
5. Identify backend modules, data and API impact.
6. Identify security/authorization impact.
7. Write acceptance criteria.
8. Split into smallest end-to-end vertical slices.
9. Check Definition of Ready.
10. Check `docs/00-governance/requirements-traceability.md` and the relevant feature/screen spec.
11. Record open decision instead of inventing an answer.

Output a plan that lists specs read, files/modules affected, acceptance criteria, tests, risks and documentation updates.
